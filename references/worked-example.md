# 반영 전후 전체 예시

모든 이름·대화·상황은 합성이다. 실제 사용자의 확인값이 아니다.

## 입력

기존 프로젝트 지침:

```markdown
# 문서 기준

- 문서는 대상 업무에 맞는 사례를 고른다.
- 기본 본문 크기는 12pt다.
```

제안서의 대표 사례는 장비 A였지만 대상 업무에는 장비 A를 다루는 행동·산출물이 없다.

사용자:

> 이 제안서에는 장비 A 말고 실제 대상 업무에 맞는 사례를 골라줘. 이 문서만 큰 글씨 16pt로 하고, 다음부터 같은 실수 안 나게 반영해줘.

## 1. 결과물을 먼저 고친다

이번 제안서의 본문을 16pt로 수정한다. 장비 A를 대표 사례에서 제외한다. 실제 대상 업무와 대체 후보 자료가 확보돼 있다면 연결 근거가 있는 사례를 고르고, 부족하면 대표 사례 선정을 보류한다. 빈칸을 피하려고 새 경험을 만들지 않는다.

같은 제안서의 재내보내기에도 16pt와 제외 상태를 유지한다. 다른 제안서에는 기존 기본값 12pt가 계속 적용된다.

## 2. 원인을 구분한다

확인 사실: `대상 업무에 맞는 사례를 고른다`는 규칙이 이미 있었다. 따라서 같은 문장을 또 추가하는 것만으로는 실행 누락을 고치지 못한다.

추정과 구분할 것: 에이전트가 파일을 읽지 않았는지, 읽고도 키워드만 보고 선정했는지는 당시 기록이 있어야 확정할 수 있다. 기록이 없으면 `선정 전 대조가 결과물에 반영되지 않음`까지만 확인 사실로 쓴다.

## 3. 기존 절을 국소 수정한다

수정 후 프로젝트 지침:

```markdown
# 문서 기준

- 대표 사례를 고르기 전에 대상 업무의 행동·산출물과 후보의 실제
  수행·결과물을 대조한다. 직접 연결 근거가 없는 후보는 대표로
  배치하지 않고, 근거가 확인된 대안 또는 부족 상태를 기록한다.
- 기본 본문 크기는 12pt다.
```

해당 문서의 작업 기록:

```text
대상: 이번 제안서
사용자 정정: 실제 대상 업무에 맞는 사례 선정, 이 문서만 16pt
변경: 장비 A 대표 배치 제외, 본문 16pt
유지: 다른 문서의 기본 본문 12pt
대안: 자료가 없으면 선정 보류; 존재·관련성을 추정하지 않음
다음 행동: 사례 선정 전에 업무 행동·산출물과 실제 수행 대조
예외: 장비 A 업무가 실제로 확인되는 다른 문서에서는 다시 검토
```

`장비 A는 나쁜 프로젝트`나 `도구 B가 모든 문서의 대표` 같은 규칙은 만들지 않는다.

## 4. 검증한다

| 검증 입력 | 확인할 행동 | 관측할 결과 |
|---|---|---|
| 이번 제안서를 다시 내보냄 | 문서별 예외 조회 | 16pt와 제외 상태 유지 |
| 새로운 일반 제안서 | 기본 지침 조회 | 12pt 사용, 후보 관련성 대조 |
| 장비 A가 직접 대상인 새 제안서 | 해당 업무·실제 수행 대조 | 이름만으로 배제하지 않음 |
| 같은 피드백 재적용 | 기존 절·기록 검색 | 새 규칙·중복 사실 행 없음 |

실제 파일 검사·렌더링·재실행을 했을 때만 실행 결과로 보고한다. 표를 읽고 판단한 것은 `수동 시나리오 대조`다.

## 5. 보고 예시

> 사례 선정 전에 업무의 행동·산출물과 실제 수행을 대조하도록 기존 기준을 보강했습니다. 이번 제안서의 16pt와 장비 A 제외는 문서별 기록으로 남겼습니다. 다른 문서의 12pt는 유지했습니다. 파일 재열람과 중복 확인을 마쳤고, 대체 사례는 자료가 없어 보류했습니다.

이 문장은 보고 형식의 예시다. 실제 수행하지 않은 검사나 확보하지 못한 자료는 자신의 보고에 복사하지 않는다.
