# 판단과 반영 위치

아래 사례는 모두 설명용 합성 예시다. 실제 사용자의 선호·경력·사실로 복사하지 않는다.

## 1. 같은 표현도 범위를 나눠 읽는다

| 관측 | 잘못된 반영 | 적절한 반영과 결정 시점 |
|---|---|---|
| `이 제안서에는 장비 A 사례가 안 맞아` | 모든 문서에서 장비 A 금지 | 이번 제안서의 제외 유지. 다음 사례 선정 전 대상 업무·행동·산출물과 실제 수행 대조 |
| `대신 검토 도구를 설명해줘` | 모든 AI 문서의 대표 사례를 검토 도구로 고정 | 이번 선택으로 반영. 다음 업무에서는 후보를 다시 비교 |
| `이 문서만 요약 빼고 학력부터` | 모든 문서의 요약 삭제 | 해당 문서와 재내보내기에만 적용 |
| `앞으로 기술명 처음 나올 때 역할도 설명해줘` | 기술명을 전부 삭제 | 같은 독자군의 설명문 작성 전에 이름과 역할을 함께 확인 |
| 질문에 `실습 준비와 진행도 했어요` | 인원·기간·성과 추가 | 해당 활동의 두 행동만 `user_reported`로 기록하고 다음 질문 전에 조회 |
| `그 플랫폼 말고 그 회사 자체 채용이요` | 모든 플랫폼 질의를 회사 자체 채용으로 해석 | 이번 질의의 대상을 고정하고 다음 모호한 요청은 기존 맥락부터 대조 |
| `한 개씩 말고 비교해서 여러 개 줘` | 미검증 후보로 숫자 채우기 | 비교 가능한 검증 후보를 묶고 적으면 실제 확보 수와 한계 표시 |
| `가르치는 역할은 이번에는 빼줘` | 교육 업종·교육 경력 전체 배제 | 해당 탐색에서 수업·지도가 핵심인 직무만 제외 |
| API 실패 또는 평점 변화 | 도구 영구 금지 또는 과거 수치 고정 | 날짜가 있는 관측으로 기록하고 다음 사용 시 현재 상태 확인 |
| 같은 규칙이 이미 있는데 오류 반복 | 날짜만 바꿔 같은 규칙 추가 | 어느 단계에서 파일을 안 읽었거나 검수를 놓쳤는지 고침 |

명시적인 `앞으로 기본으로`는 한 번의 발언으로도 지속 선호의 근거가 될 수 있다. 반대로 같은 발언이 복제 채팅에 여러 번 보인다고 독립적인 반복 확인이 되지는 않는다.

## 2. 원인별로 다른 부분을 고친다

| 확인한 원인 | 고칠 곳 | 완료 증거 |
|---|---|---|
| 결정 기준 자체가 없음 | 소유 스킬의 해당 결정 직전 | 무엇을 대조할지 명시되고 관련 입력에 적용됨 |
| 기준은 있지만 찾지 않음 | 조회 색인·호출 조건 | 다음 질문/선정 전에 소유 파일로 도달 가능 |
| 읽었지만 실행 순서에서 누락 | 해당 단계의 입력·출력·검수 | 최종 결과물의 대응 필드/위치 확인 |
| 사실값이 잘못됨 | 해당 원장의 필드 | 출처·확인일·증거 상태 일치 |
| 내용은 맞지만 설명이 어려움 | 본문·작성 스킬의 설명 기준 | 독자가 대상·기능·역할·한계를 이해할 수 있음 |
| 사용자 조건이 바뀜 | 현재 작업의 조건과 예외 | 이전 지시와 충돌하는 범위만 대체됨 |
| 도구·외부 서비스 상태 변화 | 실행 기록·실패 대응 절차 | 현재 관측과 재시도/중단 기준 기록 |

원인 자료가 부족하면 `원인 추정`이라고 쓴다. 모든 문제를 `규칙 부재`로 진단해 AGENTS를 늘리지 않는다.

## 3. 파일의 책임을 구분한다

**AGENTS.md**에는 여러 작업에 적용되는 발동 조건과 조회 경로를 둔다. 예를 들어 `재사용할 정정은 reflect-and-apply를 적용한다`는 연결이다. 상세 사례 20개를 복사할 장소는 아니다.

**SKILL.md와 참조**에는 업무 선택·실행·검수의 절차를 둔다. 자주 쓰는 핵심 기준은 본문, 조건별 상세와 사례는 참조에 둔다. 실패 연혁 대신 현재 유효한 절차를 유지한다.

**사실 원장**에는 사용자 확인값과 증거 수준을 둔다. 다음 질문 전에 찾을 수 없다면 색인·참조 연결도 점검한다. 원장 이름·경로는 환경마다 다르며 이 패키지는 특정 개인 원장을 요구하지 않는다.

**작업 기록**에는 이번 결과물의 선택·제외·배치·예외와 당시 관측을 둔다. 한번 정한 예외는 같은 작업의 재개·수정에도 유지한다.

## 4. 절차를 바꾸는 문장으로 쓴다

나쁜 예:

> 관련 있는 내용을 고르고 더 신중하게 확인한다.

개선 예:

> 대표 사례를 고르기 전에 대상 업무의 행동·산출물과 후보의 실제 수행을 대조한다. 직접 연결 근거가 없는 후보는 대표로 배치하지 않고, 연결이 확인된 대안 또는 부족 상태를 기록한다.

`도구 X 금지` 같은 이름 규칙보다 어떤 근거가 있을 때 사용할지를 정의한다. 금지 자체가 사용자의 명시적 지속 지시인 경우에는 해당 범위대로 보존한다.

## 5. 저장하지 않는 것도 결과다

다음은 확정 지침으로 저장하지 않는다.

- 사용자의 침묵이나 에이전트 자신의 과거 추천.
- 제목·검색 요약만 읽은 대화의 선호.
- 문서 양식의 빈칸을 채우기 위해 추정한 경력·성과.
- 한 번의 외부 오류에서 추론한 영구적인 도구 결함.
- 현재 요청과 무관한 개인 정보 또는 보호자료.

기존 규칙이 이미 충분하고 추가로 고칠 실행 경로가 없으면 `기존 기준으로 처리, 새 지침 변경 없음`으로 끝낸다.
