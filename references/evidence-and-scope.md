# 근거 수집과 범위 설정

## 1. 읽기 범위를 요청에 맞춘다

| 요청 | 읽기 시작점 | 확장 조건 |
|---|---|---|
| `이번 채팅 반영해줘` | 현재 사용자 메시지·대상 결과물·관련 소유 지침 | 대상이 이전 작업을 명시적으로 가리키고 현재 근거가 부족할 때 |
| `오늘 채팅 돌아봐` | 사용자 시간대의 오늘 날짜에 해당하는 관련 채팅 목록 | 실제 메시지에서 정정 앞뒤가 필요한 경우 |
| `최근 같은 실수가 반복돼` | 관련성이 높은 최근 채팅 3개 안팎 | 동일 원인인지 판단할 근거가 더 필요할 때 |
| `분석만 해줘` | 위 범위의 읽기 | 수정으로 확장하지 않음 |

개수는 시작 범위이지 성과 목표가 아니다. 관련 없는 채팅으로 수를 채우지 않는다. 시간대가 없고 날짜 경계가 결론에 영향을 주면 그 부분을 확인하거나 사용한 기준을 명시한다.

채팅 도구가 없는 환경에서는 현재 대화, 사용자가 제공한 대화 발췌, 허용된 작업 기록으로 진행한다. 도구 이름이 다르면 같은 역할의 읽기 도구를 사용한다. 접근할 수 없는 과거를 읽었다고 보고하지 않는다.

## 2. 필요한 원문만 확보한다

1. 제목·검색으로 후보를 찾는다.
2. 실제 사용자 메시지를 열어 정정·답변을 확인한다.
3. 대명사나 짧은 답변이 있으면 앞선 질문을 읽는다.
4. 필요하면 해당 결과물과 당시 지침을 대조한다.
5. 원문 위치·날짜·확인 범위를 기록한다.

긴 도구 로그, 주입된 지침 전문, 관련 없는 사적 대화를 통째로 복사하지 않는다. 출력 필터링이 가능하면 필요한 사용자 발언과 결과물 위치만 추린다. 메시지의 숨겨진 사고 과정은 근거 대상이 아니다.

## 3. 질문과 답변의 쌍을 보존한다

합성 예시:

> 질문: 이 실습에서 준비만 했나요, 진행도 했나요?
>
> 답변: 준비랑 진행도 했어요.

기록할 수 있는 것: 해당 실습에서 준비와 진행을 수행했다는 사용자 확인.

기록할 수 없는 것: 독립 강의 경력, 참가자 수, 기간, 만족도, 효과, 책임자 지위. 이전 질문이 없으면 `진행도 했다`의 대상부터 확인한다.

`거의 없음`을 `전혀 없음`으로 바꾸지 않는다. `이번에는`을 `앞으로 항상`으로 바꾸지 않는다. `작년 기준`을 현재 상태로 바꾸지 않는다.

## 4. 출처와 주장 상태를 따로 둔다

| 상태 | 의미 | 보존할 한계 |
|---|---|---|
| `user_reported` | 사용자가 해당 사실을 직접 확인 | 문서 검증·성과 검증과 별개 |
| `verified_document` | 해당 문서를 직접 열어 관련 필드를 확인 | 문서에 없는 개인 기여·범위는 증명하지 못함 |
| `observed_artifact` | 파일·화면·실행 결과를 직접 관측 | 그 버전·입력·실행 환경 범위 |
| `inferred` | 근거를 바탕으로 한 해석 | 사실 원장에 확정값으로 넣지 않음 |
| `unconfirmed` | 근거 부족 또는 원문 미열람 | 확인했다고 표시하지 않음 |

이 표의 상태명은 권장 기록 형식이다. 기존 원장에 호환되는 체계가 있으면 유지한다. 소스가 공식이라는 사실과 모든 주장이 검증되었다는 판단을 구분한다.

## 5. 중복·충돌을 처리한다

- 같은 메시지 ID가 포크에 반복되면 하나의 근거로 처리한다. ID가 없으면 원문·시점·맥락이 같은 복제인지 확인하고 불확실성을 남긴다.
- 최신 사용자 정정은 **같은 대상·필드·기간**에 적용한다. 최신 메시지라는 이유만으로 다른 문서의 유효한 예외까지 지우지 않는다.
- 원장과 사용자 답이 다르면 실제로 같은 항목인지 먼저 대조한다. 자격 취득일과 성적 발표일처럼 다른 필드를 덮어쓰지 않는다.
- 충돌이 해소되지 않으면 확정값을 새로 만들지 않는다. 관련 없는 수정은 계속 진행한다.

## 6. 최소 기록 형식

작은 수정은 기존 작업 기록에 다음 한 단락이면 충분하다.

```text
출처: 현재 채팅의 사용자 정정, YYYY-MM-DD, 메시지 위치
문제/확인값: 무엇이 틀렸거나 새로 확인됐는가
원인: 파일에서 확인한 실행 누락 / 원인 추정은 별도 표시
범위: 해당 문서 / 같은 작업군 / 특정 사실 필드
다음 행동: 어느 결정 전에 무엇을 읽고 대조할 것인가
반영: 소유 파일의 절 / 미반영·보류 이유
검증: 실제 실행한 검사와 관측 결과 / 미실행 항목
```

실제 민감한 답변은 허용된 전용 원장에만 둔다. 공용 작업 기록에는 값 대신 해당 원장의 위치와 확인 상태만 남길 수 있다.
