# 안전한 최소 수정과 되돌리기

이 절차는 허용된 로컬 지침·원장·작업 기록에 적용한다. 공개 저장소 업로드, 외부 메시지, 최종 제출 권한을 추가하지 않는다.

## 1. 소유 파일을 찾는다

1. 현재 대화의 명시적 지시를 읽는다.
2. 관련 파일과 색인에서 핵심 표현·동의어·대상 필드를 검색한다. `rg`가 있으면 우선 사용한다.
3. 검색된 파일의 관련 절과 예외를 실제로 읽는다.
4. 현재 실행에서 참조하는 소유 파일과 단순 보관본·복사본을 구분한다.

검색 결과가 없다는 이유만으로 전역 파일을 새로 만들지 않는다. 파일이 없으면 기존 연결·프로젝트 규칙을 확인하고, 요청 범위 안에서 가장 좁은 위치를 고른다.

## 2. 변경 전 상태를 보존한다

기존 버전 관리가 신뢰할 수 있으면 커밋과 diff를 활용한다. 그렇지 않으면 비공개 작업 폴더에 원본과 SHA-256을 보존한다. 백업도 원본과 같은 민감도다. 공개 패키지, 공유 폴더, Git 추적 파일에 넣지 않는다.

변경 대상·이유·기준 버전을 기록한다. 작은 수정에는 별도 관리 시스템이나 장기 이력을 만들지 않는다.

## 3. 수정 직전 다시 확인한다

백업 이후 파일의 해시나 현재 내용을 다시 비교한다.

- 같으면 계획한 국소 수정을 적용한다.
- 다르면 새 내용을 읽고 변경 의도를 최신 버전에 다시 적용한다.
- 같은 절에 충돌이 있고 안전하게 해결할 수 없으면 충돌 부분을 보류한다. 무관한 작업은 계속한다.

백업 전체를 덮어써 타인의 변경을 되돌리지 않는다. 같은 문장이 여러 곳에 있다고 전부 일괄 치환하지 않는다.

## 4. 기존 절을 고친다

일반적인 수정 단위는 다음 중 하나다.

- 기존 결정 기준에 누락된 대조 항목 추가.
- 질문 전 조회 색인에 기존 사실 원장 연결.
- 현재 작업의 예외·제외 상태 갱신.
- 잘못된 사실 필드를 출처와 함께 정정.
- 이미 중복된 규칙을 의미·예외를 보존하며 합치기.

복사본은 현재 사용·참조가 확인된 경우에만 동기화한다. 다른 스킬의 무관한 문체·설정·정책을 함께 정리하지 않는다.

## 5. diff와 재열람으로 확인한다

필수 확인:

- 요청과 연결되지 않는 변경이 있는가?
- 사용자 발언의 대상·정도·시점·주장 강도가 보존됐는가?
- 기존에 유효한 예외가 사라졌는가?
- 참조 링크가 실제 파일로 이어지는가?
- 개인정보나 대화 원문을 불필요하게 복사했는가?
- 같은 입력으로 다시 실행하면 새로운 항목이 생기는가?

미리 만든 diff만 보지 말고 실제 저장된 파일을 다시 읽는다. 결과물도 바꿨다면 해당 결과물의 검수를 별도로 수행한다.

## 6. 재실행과 되돌리기

**재실행:** 같은 근거·파일·권한으로 다시 적용한다. 새 근거가 없다면 내용·항목 수·확인일이 유지되어야 한다. 검토 기록이 꼭 필요하면 같은 작업 기록의 상태만 갱신하고 새 규칙을 추가하지 않는다.

**되돌리기:** 잘못된 범위 확장이나 사실 변경을 발견하면 이번 변경의 해당 부분만 복원한다. 이후 타인의 수정이 있으면 현재 버전과 대조해 역방향 국소 수정을 한다. 백업 이후의 모든 변경을 지우는 방식은 쓰지 않는다.

되돌린 이유·남은 유효 규칙·미해결 항목을 짧게 남긴다. 잘못 공개된 비밀이 있다면 단순 파일 삭제만으로 회수됐다고 판단하지 말고 해당 환경의 사고 대응 절차를 따른다.

## 7. 완료의 경계

| 관측 | 보고할 수 있는 것 | 보고할 수 없는 것 |
|---|---|---|
| 파일 저장·재열람 | 지침이 파일에 반영됨 | 다음 세션이 이미 자동 사용함 |
| YAML·링크 검사 | 구조와 연결이 검사 범위에서 유효함 | 의미·판단이 항상 옳음 |
| 합성 입력의 격리 실행 | 그 입력에서 해당 행동을 관측함 | 모든 실제 작업에서 재발하지 않음 |
| 새 세션에서 발견·실행 | 해당 환경·시점의 실제 발견·행동 | 모든 사용자·도구·모델에서 보장됨 |

마지막 보고는 파일 변경·다음 행동·실행한 검증·보류만 간결하게 남긴다.
